# Русские голосовые команды в Home Assistant: стенд и сырые результаты

Скрипты и данные к статье в блоге BotHub на Хабре о том, как языковые модели и движки распознавания речи справляются с русскими командами в Home Assistant.

## Что внутри

`scripts/` — стенд:

- `home.py` — 23 устройства демо-интеграции с русскими именами и комнатами.
- `bench.py` — 20 команд. Перед каждой квартира сбрасывается в исходное состояние, после команды сверяется состояние всех 23 устройств. Лишнее изменение другого устройства считается ошибкой.
- `hal.py` — обёртка над REST и WebSocket API Home Assistant.
- `proxy.py` — записывающий прокси между Home Assistant и OpenAI-совместимым API: по нему считались токены и запросы на команду.
- `llm_setup2.py` — подключение моделей через интеграцию llama.cpp (основной сервис, отдельный сервис для Gemini, ключи Pro и Eco).
- `aliases.py` — псевдонимы комнат и устройств в падежах («кухне», «люстру»).
- `bigexpose.py` — открыть ассистенту 82 устройства вместо 23.
- `hybrid.py`, `e2e.py` — прогон через assist_pipeline: с локальной обработкой команд и полный голосовой путь (распознавание, агент, озвучка Piper).
- `prep_audio.py`, `gen_piper.py`, `gen_tts1.py` — подготовка аудио: синтез фраз Piper и tts-1, розовый шум на 10 дБ тише речи.
- `stt2.py`, `stt_eval2.py` — прогон движков распознавания (GigaAM, Vosk, T-one, Parakeet через onnx-asr, Whisper через faster-whisper, whisper-1 через API) и подсчёт WER после нормализации.
- `tts_bench_piper.py` — скорость синтеза Piper.
- `summ.py` — сводка по моделям.

`results/` — сырые ответы:

- `results_lane*.jsonl` — каждая команда каждой модели: текст ответа, время, запросы к API с токенами, какие устройства изменились.
- `results_builtin.jsonl` — встроенный агент без псевдонимов и с ними.
- `results_big2.jsonl` — DeepSeek V4.1 Flash на 82 устройствах.
- `e2e.jsonl` — голосовой путь на живых записях: распознанный текст, время распознавания, агента и озвучки, прогон без интернета.
- `stt_new.jsonl`, `stt_summary2.json` — распознавание речи: гипотеза каждого движка на каждой записи и сводка WER.
- `llm_table.json` — итоговая таблица по моделям.

## Как запустить

Нужны Docker, Python 3.12+ и ключ любого OpenAI-совместимого API.

1. Поднять Home Assistant (`ghcr.io/home-assistant/home-assistant:stable`) с `demo:` в `configuration.yaml`, пройти онбординг, сохранить долгоживущий токен в `llat.txt`.
2. Запустить `home.py`-разметку (имена и комнаты) и открыть ассистенту 23 устройства.
3. Положить ключ в `keys.env` строкой `pro=...`, запустить `proxy.py`, затем `llm_setup2.py`.
4. `python3 bench.py conversation.<агент> "<метка>" results.jsonl`.

Файл `keys.env` в репозиторий не кладётся.
